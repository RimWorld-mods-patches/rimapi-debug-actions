# RIMAPI Debug Actions development settings

Shared workflows are vendored at `.shared/rimworld-dev-skills` and discovered
through `.agents/skills` and `.claude/skills`. Read `.rimworld-dev.json` for this
checkout's project, shipped DLL and baseline active-mod order. Update the
snapshot from a clean checkout with:

```sh
sh .shared/rimworld-dev-skills/scripts/update-subtree.sh
```

## Consumer-specific assertions

- Framework/reference pin: net472 / RimWorld 1.6.4871, RIMAPI 1.10.0.
- The build downloads the pinned RIMAPI release and checks its SHA-256
  (`RimApiVersion`, `RimApiSha256` in the project); no Steam path is needed.
  Change both properties together.
- Only `RimApiDebugActions.dll` belongs in `1.6/Assemblies/`. RIMAPI's
  assemblies must never be copied into this mod.
- There are no unit test projects. Live verification uses the
  `use-rimapi-debug-actions` skill against a loaded game with the baseline mods
  enabled: the list route returns actions with `is_runnable`, and running a
  parameterless static action returns `success: true` with its effect in the
  log. A consumer mod's disposable profile (for example Realistic Bases') can
  serve as the test game.
- Never run actions in a normal profile: they mutate the loaded game.
